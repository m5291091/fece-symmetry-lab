## 0. 先に訂正 — レベル3だけでは根本的には治らない

「根本的に治すならレベル3」というのは、半分だけ正しい。

**仮に測定を完璧にできたとする。** 検出誤差ゼロ、姿勢の影響ゼロ、3Dも完璧。そのとき画面に何が出るか：

| | 真の d | 現行の表示 |
|---|---|---|
| 対称な成人（文献値） | 0.0241 | **97.59%** |
| 非対称な成人（文献値） | 0.0452 | **95.48%** |

**測定が完璧でも、画面は 97.59% と 95.48% のまま。** 何も変わらない。

### 体温計のたとえ

いま起きていることは、こういう体温計を作っているのと同じ。

```
体温を「絶対零度からの割合」で表示する体温計

   平熱 36.5℃ = 309.65K  →  「100% 中 99.36%」
   発熱 38.5℃ = 311.65K  →  「100% 中 100.00%」  ← 上限に張り付く
```

センサーを 0.001℃ まで測れるように改良しても、**画面の数字は読めるようになりません。** 分母（絶対零度からの距離）が大きすぎるので、意味のある差が小数点以下に潰れてしまうからです。

いまの対称度も同じ構造です。分母が「両眼間距離 63mm」で、測りたい差は「1.3mm」。センサー（レベル3）を良くしても、目盛り（レベル1）を直さない限り読めません。

### 3つの層は、それぞれ別の問題を塞ぐ

```
┌─────────────────────────────────────────────┐
│ ③ 表示の層（レベル1）                        │
│   測った量を、人が読める尺度に載せられているか  │  ← レベル3では直らない
├─────────────────────────────────────────────┤
│ ② 指標の層（レベル2）                        │
│   測った量から、姿勢の成分を分離できているか    │  ← レベル3では直らない
├─────────────────────────────────────────────┤
│ ① 測定の層（レベル3）                        │
│   そもそもノイズより大きく測れているか          │  ← ここだけがレベル3
└─────────────────────────────────────────────┘
```

- **レベル3だけ**やると → 精密に測れるようになるが、画面は相変わらず 97.6%
- **レベル1だけ**やると → 読みやすくなるが、読んでいるのは誤差のゆらぎ
- **両方いる。** どちらか片方では意味がない

以下、レベル3の中身を詳しく見ていきます。

## 1. なぜ姿勢がここまで効くのか — `2·z·sinθ` という式

### 直感

正面から撮った顔写真と、少し横を向いた写真を思い浮かべてください。横を向くと、**こちら側の頬が広く、向こう側の頬が狭く**写ります。

これは顔が非対称になったわけではなく、回転して撮っただけ。でも **2D の点だけを見ている限り、この2つは区別がつきません。**

### 式で見ると

顔を角度 θ だけ横に向けます。奥行き `z` にある点は、横方向へ `z·sinθ` ずれて写ります。

左右のペアは **同じ奥行き `z`** を持つので（顔が対称なら当然そうなる）、**両方とも同じ向きに** ずれます。

```
    左の点 (-x, z)  →  -x·cosθ + z·sinθ
    右の点 (+x, z)  →  +x·cosθ + z·sinθ

    右を鏡に映す    →  -x·cosθ - z·sinθ
    ───────────────────────────────────────
    左との差        =           2·z·sinθ     ← 顔の形と無関係に湧く
```

`x`（横位置）の項はきれいに消えて、**`z`（奥行き）だけが残ります。**

### だから「奥行きのある部位」ほど壊れる

| 部位 | 平均の奥行き `z` | yaw 5° で湧く偽ズレ `2z·sinθ` |
|---|---|---|
| **輪郭** | **28.4mm** | **4.95mm** |
| 目 | 10.2mm | 1.78mm |
| 鼻 | 7.6mm | 1.32mm |
| 口 | 6.1mm | 1.07mm |

比較のため：**「対称な成人」と「非対称な成人」を分ける差は 1.33mm。**

輪郭は、首を **5°** ひねるだけで、その差の **3.7倍** の偽ズレを出します。輪郭は全体値の 27% を占めるので、そのまま総合値に効きます。

## 2. 対策9：yaw ゲートを絞る → 単独では非現実的

実顔に近い奥行きを与えた3Dモデルを、**完全に左右対称のまま** yaw させて測った結果：

| yaw | 表示 | mm換算 | 信号全幅の何倍 |
|---|---|---|---|
| 0° | 100.00% | 0.00mm | 0.0x |
| **1°** | **98.93%** | **0.68mm** | **0.5x** |
| 2° | 97.85% | 1.35mm | 1.0x |
| 3° | 96.78% | 2.03mm | 1.5x |
| 5° | 94.62% | 3.39mm | 2.5x |
| 8° | 91.37% | 5.44mm | 4.1x |
| **15°（現行ゲート）** | **83.54%** | 10.37mm | **7.8x** |

**姿勢由来の誤差を信号より小さく抑えるには、yaw を ±1° に絞る必要があります。**

これは人間に守らせるのは無理です。呼吸や瞬きでも 1° は動きます。ゲートを絞るほど「HOLD」で止まる時間が増え、実用性がなくなります。

### 現実的な代案

**ゲートを絞る代わりに、yaw に応じた誤差バーを併記する。**

```
偽ズレの大きさ ≈ 2 × RMS(z) × sin(yaw)
```

`z` は3Dモデルから分かる既知の量、`yaw` は `domain/pose.py` がすでに出しています。**両方揃っているので、いま計算できます。**

```
対称度 96.5%  ± 2.0%（yaw 3.2° に由来）
```

こう出せば「この数字は姿勢のせいでこれだけブレている」と正直に言えます。ユーザーを止めずに、誤読も防げる。

## 3. 対策10：複数フレームで平均する → 「何を」平均するかで結果が正反対

**これがレベル3の中で最も費用対効果が高く、しかも現行実装が間違った側にあります。**

### 射的のたとえ

的の中心を狙って何発も撃つとします。狙いは正確（＝顔は本当に対称）ですが、手がブレる（＝検出誤差）。

**記録の仕方が2通りあります。**

```
【A】「中心からの距離」だけを記録する
     右に5cm外れた → 「5cm」
     左に5cm外れた → 「5cm」
     ↑ 距離は必ずプラス。左右で打ち消し合わない

     100発の平均 = 5cm       ← 何発撃っても 0cm にならない


【B】「当たった位置（座標）」を記録する
     右に5cm外れた → 「+5cm」
     左に5cm外れた → 「-5cm」
     ↑ 符号があるので打ち消し合う

     100発の平均 = 0.5cm     ← 1/√N で中心に近づく
```

**`d` は【A】です。** `d = ||左 - 鏡映(右)||` は距離なので必ず 0 以上。だから検出誤差は **`d` を押し上げる方向にしか働きません**（これを「正のバイアス」と呼びます）。

**landmark 座標は【B】です。** 符号があるので、平均すれば誤差が打ち消し合います。

### 実測

完全に対称な顔・yaw 0°・MediaPipe Full 相当の誤差。**真の `d` は 0.0000** です。

| フレーム数 N | `d` を平均した場合 | **座標を平均した場合** |
|---|---|---|
| 1 | 0.0742 (92.58%) | 0.0742 (92.58%) |
| 5 | 0.0729 (92.71%) | 0.0330 (96.70%) |
| 10 | 0.0735 (92.65%) | 0.0230 (97.70%) |
| 30 | 0.0727 (92.73%) | 0.0133 (98.67%) |
| **100** | **0.0729 (92.71%)** | **0.0073 (99.27%)** |

- **`d` を平均**：N をいくら増やしても `0.073` のまま。**100倍がんばっても 1mm も改善しない。**
- **座標を平均**：`1/√N` で真値 0 に近づく。10フレームで 3.2倍、100フレームで 10倍の改善。

### 現行実装の位置

```python
# domain/smoothing.py
class TimeBasedEma:
    def update(self, raw: float, *, at: float) -> float:   # ← raw は d（スカラー）
        ...
        self._value = float(alpha * raw + (1.0 - alpha) * self._value)
```

**`TimeBasedEma` は `d`（スカラー）を平滑化しています。上の表の左側、効かない側です。**

平滑化の対象を landmark 座標（`(478, 2)` の配列）へ移すだけで、10フレームで 3.2倍の改善が得られます。EMA の式はそのまま使えます（配列に対して要素ごとに適用するだけ）。

> 補足：`d` の平滑化にも「表示のチラつきを抑える」という別の役割はあるので、消す必要はありません。**座標側の平滑化を追加する**のが正解です。

### ただし、平均で消えないものがある

| 誤差の種類 | たとえ | 平均すると |
|---|---|---|
| **ランダム誤差** | 手ブレ | 何枚も重ねれば消える（`1/√N`） |
| **系統誤差** | カメラが最初から傾いている | 何枚撮っても全部傾いている。**消えない** |

実測：

```
yaw 3° で座り続けた場合、100フレーム平均しても d=0.0331 (96.69%) のまま
yaw 5° で座り続けた場合、100フレーム平均しても d=0.0543 (94.57%) のまま
```

**いつも同じ姿勢で座る人は、100フレーム平均しても同じ誤差を持ち続けます。** また §4.3 のテンプレート由来のバイアス（検出器が実物より対称なメッシュを出す傾向）も系統誤差なので、平均では減りません。

だから対策10だけでは足りず、姿勢そのものを扱う対策11が要ります。

## 4. 対策11：3Dで測る → 姿勢の影響が原理的に消える

### なぜ3Dなら消えるのか

**2D では、回転すると形が変わって見えます。** だから「姿勢のせいで変わったのか」「顔が非対称なのか」を区別できません。

**3D なら、回転は「向きが変わっただけで形は同じ」と扱えます。** 回転しても点と点の距離は変わらないからです。

### 折り紙のたとえ

いまのやり方はこうです：

```
【現行】 先に折り目を決めてから折る
   1. 鼻筋の27点に直線をあてはめる     ← ここで折り目を決め打ち
   2. その線で折る
   3. ズレを測る

   問題：折り目の決め方が悪いと、折り目のせいでズレが出る
        （§5.2 の「測っていない正中線点が全部を動かす」問題）
```

3D のやり方はこうです：

```
【3D object symmetry 解析】 重ねてみて、一番よく重なる置き方を探す
   1. 3D の点群 X を用意する
   2. X を鏡に映し、左右のペア名を入れ替えたものを M(X) とする
   3. M(X) を X の上に、最小二乗で一番よく重なるように動かす
      （＝ Procrustes 重ね合わせ）
   4. 重ねきれずに残った距離が、本当の左右差

   ポイント：折り目を先に決めない。重ね合わせが最適な折り方を自動で見つける
```

これは形態計測学（morphometrics）で **object symmetry 解析** と呼ばれる標準手法です。

**なぜ姿勢に依存しないか：** `X` 全体を回すと `M(X)` も同じだけ回るので、両者の相対関係は変わりません。だから重ね合わせた後の残差も変わりません。

### 実測

| yaw | 現行 2D | 3D object symmetry |
|---|---|---|
| 0° | 100.00% | 100.00% |
| 3° | 96.78% | **100.00%** |
| 5° | 94.62% | **100.00%** |
| 8° | 91.37% | **100.00%** |
| 15° | 83.54% | **100.00%** |

**yaw が何度でも `d = 0.0000`。姿勢の影響が完全に消えています。**

副次的な効果として、§5.2 の「正中線点が全部を動かす」問題も同時に消えます。折り目を先に決めないので、正中線点という特別扱いの点群が不要になるからです。

### ただし代償がある — z の精度

3D にすると、z 座標の誤差が新しく入ってきます。

| z の誤差 | 完全対称な顔でも出る `d` |
|---|---|
| 2% IOD | 0.0273 (97.27%) |
| 5% IOD | 0.0683 (93.17%) |
| 10% IOD | 0.1367 (86.33%) |

**z の誤差が 5% IOD あると、`d = 0.068`。これは yaw 8° 相当（0.086）とほぼ同じです。** つまり yaw を消した分をそのまま z の誤差で失います。

MediaPipe は z を出しますが、**z の精度は公表されていません**（論文の 3.96% IOD は xy の値）。構造上、z は 2D 画像から推定した「推測値」なので、xy より悪いはずです。

**だから3D化に進むかどうかは、z の精度を実測してから決めるべきです。**

```
判断基準:
  z の誤差 < 2% IOD  →  3D 化は勝ち。yaw 問題が原理的に消える
  z の誤差 > 5% IOD  →  意味がない。yaw を消した分を z で失う
  その間             →  yaw の実測分布と比べて判断
```

## 5. 結局、根本的に治すには

### 3つの層を、それぞれ塞ぐ

| 層 | 何を解決するか | 具体策 | コスト |
|---|---|---|---|
| ① 測定 | ノイズ > 信号 を逆転させる | **座標を平均**（対策10）→ 10倍改善 | 小 |
| ② 指標 | 姿勢を非対称から分離する | **3D object symmetry**（対策11）または **DA/FA 分解**（対策6） | 中〜大 |
| ③ 表示 | 測った量を読める尺度に載せる | **mm換算 / percentile / SNR**（対策1〜3） | 小 |

**この3つを揃えて初めて「治った」と言えます。** どれか1つでは、他の2つがボトルネックになって効果が出ません。

### 費用対効果の順

```
1位  座標平均（対策10）        smoothing の対象を移すだけ。10倍改善。★最優先
2位  表示改修（対策1〜3）       d も metric_version も据え置き。リスクほぼゼロ
3位  yaw 誤差バー（対策9の代案） pose.py の出力を使うだけ。誤読を防げる
4位  DA/FA 分解（対策6）        既存の計算の集計を変えるだけ。姿勢成分を切り出せる
5位  3D 化（対策11）           効果は最大だが、z 精度の実測が前提。設計変更も大きい
```

**1位と2位だけで、実用上かなり改善します。** 3D化（5位）は「原理的に正しい解」ですが、前提条件（z の精度）が未確認なので、いま飛びつくのは早いです。

### 実装の順番

```
テストB（再現性を測る）
    ↓  ← ノイズ床が分かる。ここが全ての判断基準になる
座標平均を入れる（対策10）
    ↓  ← テストB をもう一度回して、ノイズ床が 1/√N に下がったことを確認
表示を直す（対策1〜3）
    ↓
テストD（z の精度を測る）
    ↓  ← 良ければ
3D object symmetry へ（対策11）
```

**最初にテストBをやるのが重要です。** ノイズ床が分からないと、対策の効果を測れません。「良くなった気がする」で進めると、何が効いたのか分からなくなります。

## 6. まとめ

**質問：根本的に治すにはレベル3にすればいいのか？**

**答え：レベル3は「正しく測れるようにする」だけで、「読めるように見せる」は別問題です。**

- レベル3を完璧にやっても、画面の数字は 97.59% と 95.48% のまま（§0）
- レベル1（表示）を直さない限り、精度を上げた分は画面に出てこない
- 逆にレベル1だけ直しても、見えているのは誤差のゆらぎ

**両方いります。** そして順番としては、

1. **レベル3の対策10（座標平均）** — 最も安く、最も効く。しかも現行実装が間違った側にある
2. **レベル1（表示改修）** — リスクがほぼゼロで、潰れている情報を取り戻せる
3. あとはテスト結果を見ながら

というのが現実的です。レベル3のうち yaw ゲート（対策9）は単独では非現実的、3D化（対策11）は原理的に正しいが前提条件の確認待ち、という位置づけになります。
