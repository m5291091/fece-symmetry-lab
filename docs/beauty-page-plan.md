## 2. 機能別 設計方針

### S. 対称性スコア + パーセンタイル化

**問題**: 現状スコアがほぼ90%超に張り付き、識別力がない。

**原因は2つあり、両方に対処する。**

1. **スコアの分布が上端に潰れている** → パーセンタイル化で解決
2. **頭部姿勢による測定誤差がスコア差を埋めている** → 姿勢補正で解決

**対処1: 参照分布の事前構築**

公開データセット（後述 §4）から N=500〜2000 枚を処理し、生スコアの分布を求めて **configs/metrics/ 配下に凍結した分位点テーブル（JSON）として同梱**する。実行時はテーブル参照のみで、DBもネットワークも不要。既存の `configs/metrics/symmetry-2d-v1.json` と同じ「凍結バンドル」パターンに乗せる。

表示は「92.4%」ではなく **「上位 18%（同世代の分布内）」** とする。生スコアは補助情報として併記。

**対処2: 頭部姿勢の正規化**

既存 `domain/pose.py` の yaw/pitch/roll を用い、正面基準へ補正してからスコアを算出する。補正の有効性は、同一人物を複数角度で撮影しスコア分散が縮小することで定量的に示す。**これを発表会の技術的貢献の中核に据える。**

**受け入れ基準**

- AC-PCT-01: 参照分布に対する分位点変換後、テストセットのスコア分布の標準偏差が生スコアの3倍以上に拡大すること
- AC-POSE-01: 同一被験者を yaw ±15° の範囲で撮影したとき、補正後スコアの標準偏差が補正前の 50% 以下になること

---

### B. メイク・眉の左右差チェック

**狙い**: 骨格の左右差より**大きく散らばる**指標であり、90%問題が構造的に起きない。かつ根拠が landmark 間の実測値のみで説明でき、価値判断を含まない。

**出力する指標**

| 指標 | 算出 |
|---|---|
| 眉頭の高さ差 | 左右の眉頭 landmark の正中線垂直距離の差 |
| 眉山の高さ差 | 同上（眉山点） |
| 眉の角度差 | 眉頭→眉山ベクトルの水平からの角度、左右差 |
| 眉の長さ差 | 眉頭〜眉尻の弧長の左右比 |
| 目の開き幅の差 | 上下瞼間距離の左右比 |
| 目尻の高さ差 | 外眼角の正中線垂直距離の差 |
| 口角の高さ差 | 口角 landmark の正中線垂直距離の差 |

**表示規約**

- 単位は**両目間距離（IPD）で正規化した相対値**とし、参考値としてミリ換算も併記（IPD を成人平均 63mm と仮定、その旨を明記）
- 「良い / 悪い」の語を使わない。「左が 1.8mm 高い」という事実提示のみ
- オーバーレイで該当部位を左右比較表示

**受け入れ基準**

- AC-MAKEUP-01: 左右対称に合成した検証画像に対し、全指標が 0 近傍（IPD比 0.005 未満）を返すこと
- AC-MAKEUP-02: 片眉を既知量だけ平行移動させた合成画像に対し、検出値が真値の ±10% 以内であること

---

### C. 対称化モーフィング・スライダー

**既存の `application/symmetrization.py` を拡張する。新規実装ではない。**

**追加要素**

1. **連続パラメータ化**: 現状の一発処理（0 or 100%）を、`alpha ∈ [0, 1]` の連続補間に拡張。目標点群を `p + alpha * (p_sym - p)` として区分アフィンワープへ渡す
2. **3面比較ビュー**: 元の顔 / 左半分ミラー / 右半分ミラー を横並び表示
3. **UI**: Streamlit スライダー。静止画のみ対象（リアルタイム適用は性能リスクのため対象外）

**性能要件**: 静止画 1024px 長辺で 1 スライダー操作あたり 300ms 以内。超える場合は解像度を落としたプレビューを表示する。

**受け入れ基準**

- AC-MORPH-01: alpha=0 で入力画像とピクセル一致すること
- AC-MORPH-02: alpha=1 で既存の対称化出力と一致すること
- AC-MORPH-03: alpha を 0→1 に動かしたとき、対称性スコアが単調非減少であること

---

### D. リアルタイム・ベストアングルコーチ

**講義パイプライン（Camera → Preprocess → AI Model → Result → **Feedback**）への適合を明示できる機能。Theme 4（ヨガ・ポーズコーチング）の構造を顔に適用した形として発表で説明する。**

**動作**

1. カメラフレームごとに姿勢補正済み対称性スコアを算出
2. 正面からのズレに応じた指示を表示（「顎を少し引く」「左に5°」「もう少し正面へ」）
3. セッション中の最高スコアフレームを自動保持し、終了時に提示

**実装方針**

- 指示生成は既存 `ui/guidance.py`（位置誘導メッセージ）を拡張する
- 最高スコアフレームの保持は `application/session.py` のセッション内メモリに置く（DB不要）
- 既存 `runtime/frame_scheduler.py`（latest-frame-wins）と `domain/smoothing.py`（表示平滑化）をそのまま使い、指示のちらつきを抑える
- 指示の切り替えには**ヒステリシス**を入れる（既存 `application/quality.py` と同方針）。閾値近傍で指示が高速に往復するのを防ぐ

**受け入れ基準**

- AC-COACH-01: yaw が閾値を跨いで振動する入力列に対し、指示メッセージの切り替え回数がヒステリシスなしの場合の 30% 以下であること
- AC-COACH-02: ベストフレームの更新が、平滑化後スコアの最大値と一致すること

---

### F. パーツ別「あなたの強み」表示

**狙い**: 総合点による序列化を避けつつ、個別化された情報を返す。倫理面の緩衝材でもある。

**方針**

- 各部位（目・眉・鼻・口・輪郭）の対称性を**自分自身の中で相対比較**し、レーダーチャートで表示
- 最も対称な部位を「あなたの強み」として1つ提示
- 他人との比較は行わない（パーセンタイル化は S の総合スコアのみに適用し、部位別には適用しない）

**受け入れ基準**

- AC-PART-01: 全部位が同値の入力に対し、恣意的な順位付けをせず「差がない」と表示すること

---

### T. 顔タイプ分類 → 髪型提案・着せ替え・タイプ変換

**T-1. 顔タイプ分類**

landmark から算出する幾何特徴で**ルールベース分類**する。学習モデルは使わない（学習データの偏りリスクと工数の両方を回避）。

| 軸 | 特徴量 |
|---|---|
| 縦横比 | 顔の高さ / 顔幅 |
| 顎の形状 | 下顎輪郭の曲率、顎先の尖り |
| 頬骨の張り | 頬骨幅 / 下顎幅 |
| 額の広さ | 額の高さ / 顔の高さ |

上記から 卵型 / 丸型 / 面長 / ベース型 / 逆三角形 / 四角型 の6分類。**単一ラベルではなく各タイプへの近さを比率で表示**する（「卵型 60% / 面長 30%」）。境界付近での断定を避けるため。

**T-2. 髪型提案**

タイプ別の推奨・非推奨をルールテーブル（JSON）として持つ。**出典を明記**し、美容業界の一般的知見であって科学的根拠ではないことを UI に明示する。

**T-3. 髪型着せ替え**

- 静止画のみ対象
- 髪型は**PNG 素材（透過）を landmark 基準でアフィン変換して合成**する方式。生成モデルは使わない（実行時間・再現性・工数の全てで不利）
- 既存 `adapters/inference/mediapipe_segmenter.py`（セグメンテーション）で人物マスクを取得し、髪領域の前後関係を処理
- 素材は **5〜8種類**に絞る。ライセンスが明確なもののみ使用し、`NOTICE` に記載

**T-4. 顔タイプ変換**

任意のタイプを選択すると、そのタイプの代表的な輪郭比率へ顔をワープする。**C のモーフィング基盤をそのまま流用する**（目標点群が「対称化した点群」から「目標タイプの点群」に変わるだけ）。

変形量には**安全上限**を設ける（既存 `domain/warp_mesh.py` の安全ガードを踏襲）。過度な変形で破綻した画像が出ることを防ぐ。

**受け入れ基準**

- AC-TYPE-01: 各タイプの代表比率をもつ合成顔に対し、該当タイプの比率が最大になること
- AC-TYPE-02: 髪型合成時、髪素材が顔 landmark の額基準点に規定の誤差内で整合すること
- AC-TYPE-03: タイプ変換の変形量が安全上限を超える入力に対し、上限でクリップされ破綻しないこと

## 4. 参照分布データセット

パーセンタイル化のための分位点テーブル構築に使用する。**候補は以下。ライセンスと再配布条件を確認のうえ最終決定する。**

| 候補 | 想定用途 | 確認事項 |
|---|---|---|
| CelebA / CelebA-HQ | 大規模・多様。分布構築に適する | 研究目的限定の条項 |
| FFHQ | 高品質・正面寄り。姿勢補正の検証に適する | ライセンス条件 |
| UTKFace | 年齢・民族の属性付き。層別分布に使える | 配布状況 |

**重要**: 画像そのものは同梱せず、**算出済みの分位点テーブル（数値のみ）を同梱する**。これにより配布物のライセンス問題とサイズ問題を同時に回避する。

**層別化**: 可能であれば年齢帯で分位点を分ける（「同世代の中で上位N%」のほうが情報として妥当）。既存の年齢推定（`opencv_demographic_estimator.py`）が使える。データ量が不足する場合は全体分布のみとし、その旨を明記する。

## 5. 実装順序とリスク

技術的な山は **ワープ処理**に集約されるが、これは既に実装済み。したがってリスクは相対的に低い。

| 週 | 作業 | 備考 |
|---|---|---|
| 第1週 | S: 姿勢補正 + 参照分布構築スクリプト | 最も研究価値が高い。最初に着手 |
| 第2週 | S: パーセンタイル表示、F: パーツ別レーダー | 既存スコア基盤の延長 |
| 第3週 | B: メイク・眉左右差、C: モーフィング連続化 | C は既存拡張のみで軽い |
| 第4週 | T-1/T-2: タイプ分類・髪型提案 | ルール + JSON |
| 第5週 | T-3/T-4: 着せ替え・タイプ変換 | **最大のリスク箇所** |
| 第6週 | D: ベストアングルコーチ | 既存 guidance の拡張 |
| 第7週 | 統合・検証・発表資料 | |

**リスクと対策**

| リスク | 対策 |
|---|---|
| 髪型素材のライセンス確保が難航 | 第1週の時点で素材調達を並行開始する。最悪の場合、着せ替えはシルエット（単色）表示に縮退 |
| 参照データセットのライセンス | 分位点テーブルのみ同梱する方式で回避。取得自体が困難なら、自前撮影 + 合成データで縮小版を作り、サンプル数を明記して限界を正直に述べる |
| T-3/T-4 が間に合わない | T-4（タイプ変換）を優先し、T-3（着せ替え）を切る。T-4 は既存ワープ流用で確実性が高く、デモ映えも十分 |
| リアルタイム性能 | C・T は静止画限定と最初から決めている。D のみリアルタイムで、既存 frame_scheduler で担保済み |

## 6. 倫理方針（発表資料にも1枚割く）

顔にスコアを付ける機能は容姿不安を助長しうる。以下を設計に組み込む。

| 方針 | 実装 |
|---|---|
| 単一の「美しさ点数」を出さない | 総合点ではなく部位別・比率別に分解して提示 |
| 他人との比較・ランキングを作らない | パーセンタイルは分布内位置の統計的表示に留め、個人間比較UIは持たない |
| 中立的な語彙 | "beauty" ではなく "balance / harmony"。「良い/悪い」を使わない |
| 弱点でなく特徴として提示 | F の「強み表示」で必ずポジティブな情報を返す |
| 免責の明示 | About ページに、医療・診断でないこと、黄金比の科学的根拠が限定的であること、データセット由来の偏りがあることを記載 |
| 対比による相対化 | 発表の締めに「対称性が高い顔＝魅力的とは限らない」ことを示す資料を1枚入れる |

**黄金比について**: Marquardt マスクをはじめとする黄金比ベースの美的評価は、査読研究で「実際の魅力度評価との相関が弱い」「特定の人口集団に偏る」と繰り返し批判されている。**本プロダクトでは黄金比を主要スコアの根拠として使わない。** 参考情報として表示する場合も、その限界を併記する。

## 7. 発表会での主張の骨子

1. **問題提起**: 顔の対称性スコアは実運用で 90% 台に潰れ、識別力を失う
2. **原因分析**: (a) 分布の上端集中 (b) 頭部姿勢による測定誤差
3. **手法**: 姿勢正規化 + 参照分布による分位点変換
4. **定量評価**: 補正前後のスコア分散の比較（同一被験者・複数角度）
5. **応用**: 部位別分解、メイク左右差検出、顔タイプ分類と髪型提案
6. **デモ**: モーフィング・着せ替え・リアルタイムコーチ
7. **倫理と限界**: 黄金比の妥当性への言及、容姿不安への配慮、今後の課題（時系列トラッキング）

講義の8テーマとの対応: Theme 5（表情・顔解析）と Theme 7（顔からの属性推定）の延長。新テーマ枠に **"Facial Aesthetics & Symmetry Analysis"** として提案可能。パイプライン（Camera → Preprocess → AI Model → Result → Feedback）にそのまま適合する。
