## 何が変わったか

実測前の計画は「ノイズが大きいので座標平均で下げる」だった。実測が示したのは違う話だった。

**現行の 2D 指標は精度不足ではなく、部位によって符号が逆に出る。**

| 非対称を注入したときの指標の応答 | 現行 2D | 3D |
|---|---|---|
| 目 | **−0.008（無反応）** | +0.200 |
| 鼻 | **−0.472（逆向き）** | +0.057 |
| 口 | +0.147 | +0.238 |
| 輪郭 | +0.905 | +0.138 |

鼻を非対称にすると、現行指標は「より対称になった」と報告する。これは較正で直る種類の問題ではない。

さらに:

- 同じ顔を 2 回測って **2D は 75% 違う値**を返した（3D は 4%）
- 現行の信号 ÷ ノイズ床は **0.79x** — 人と人を区別できていない
- **2D Procrustes では姿勢依存が落ちない**（+0.854 → +0.842）。効いているのは z であり、z を使わずに済ませる道は無い
- **座標平均は姿勢の「オフセット」には無力**（take02 で平均値が動かなかった）。主対策にはならない

したがって **3D object symmetry 化が必要条件**であり、座標平均は補助手段へ降格する。

## 背景

docs/symmetry-metric-measurements.md §9 を先に読んでください。実測で確認済みの欠陥です。

対称化ビジュアライゼーション（FR-034/FR-035）の変形メッシュで、三角形が裏返ります。

  1 フレーム 949 三角形のうち、中央値 7 個・最大 12 個が裏返る（実写 60 枚で計 421 個）
  裏返りは全件が顔ランドマーク領域の内側。外周アンカーを含むものは 0 件
  対称化変位の最大は 2.37〜3.56mm で、変位ガード 15.75mm は一度も働かない

原因は 2 つの量を取り違えていることです。

  変位ガード = 1 点の *絶対* 変位の上限
  裏返り     = 隣接点の *相対* 変位が点間隔を超えるか

前者は後者を含意しません。対称化変位は各ペアの実測ズレの半分で決まるので、
隣り合う landmark が別々のズレを持てば相対変位が生じます。密な領域では点間隔が
数 px しかなく、1.2〜5.4px の相対変位で符号が反転します。

`domain/warp_mesh.py` の `is_degenerate_triangle` は `triangle_area`（絶対値）が
`MIN_TRIANGLE_AREA_PX = 1e-3 px²` 未満かだけを見ており、**source と target の
向きを比較していません。** 裏返りは符号を反転させますが |面積| を縮めないので、
判定を素通りします。

  通過条件 = sign(area_source) ≠ sign(area_target) かつ 両方の |area| ≥ 1e-3 px²

実測 421 件すべてが通過。261/421 件は両側とも 1px² 超で、細長い縁ではない本物の
反転です。裏返った三角形は逆向きのアフィンで画素を転送するため、出力画像が
局所的に破綻します。

現状の視覚的影響は小さい（面積中央値 6〜19px²、1 枚あたり合計 10²px² 程度）。
しかし機構は実在し、非対称が大きい被写体ほど拡大します。

## 背景 — なぜこれが最優先になったか

E1（§12）で分かったこと:

  同一人物の 2 テイクで 3D 表示値の中央値が動いた量   0.031pt
  同じものを現行 2D で測ったとき                     4.080pt

**3D は「先週の自分と比べる」が初めて成立しうる再現性を持っています。** これは
E1 以前には期待していなかった性質で、表示設計（W5）の中心になりえます。

ところが §1 の測定条件のとおり、take01 / take02 は landmarker を直接叩いて取得
しており、**`TrackingZoomLandmarker` を通していません。** `ui/camera.py` は
リアルタイム経路の landmarker を常にこれで包むので、実際に利用者が見る `z` は
すべて `domain/tracking_zoom.py` の `remap_depths` を経由します。

  return tuple(depth * window.width for depth in depths)

この写像は §8.1.1 の「`z` は画像の幅で正規化される」というスケール規約から
導いたもので、**一度も実測で確かめていません。**

リスクの形:

  一定倍率で外れている       → d_3d が定数倍ずれるだけ。姿勢不変性は壊れない
                                W3 は進められる（要件へ事実として記録する）
  窓の大きさに応じて外れる   → 被写体が動くたびに倍率誤差が変動する
                                ＝ 3D 化で消したノイズが別経路で戻る
                                ＝ セッション間 0.031pt が成立しない

`z` のスケール誤差は §8.5.1 の正規化（3D 両眼間距離）を通じて xy との比率を歪める
ので、定数倍としてきれいに相殺されません。

### 主実験 — 窓の大きさだけを変える（統制実験）

実写だと「被写体が動いた」と「窓が変わった」が同時に起きて分離できません。まず
**1 枚のフレームを固定し、切り出し窓の大きさだけを人工的に変えて**測ってください。

  1. 顔が写っている 1 フレームを取る
  2. 顔を必ず含む切り出し窓を、大きさを変えて複数作る（例: 窓幅 0.3〜1.0 を
     数点。実際の policy が取りうる範囲に合わせる）
  3. 各窓で zoom 経路と同じ処理（切り出し → 拡大 → 検出 → `remap_depths` と
     xy の逆写像）を通し、全フレーム座標系の `(x, y, z)` を得る
  4. 窓幅に対して `d_3d` と `z` がどう動くかを見る

**対照を必ず置いてください。** 切り出しは検出器への入力画像そのものを変えるので、
`z` の写像が正しくても検出結果は動きます。`xy` だけで作った `d_2d`（および
`d_2d` の Procrustes 版）を同じ窓で測り、**「z 由来の窓依存」と「検出が変わった
ことによる窓依存」を分離**してください。これを分けないと結論が出ません。

### `z` のスケール係数 α を直接推定する

フレームごとに、直叩きの `z_direct` と zoom 経路の `z_zoom` を最小二乗で結び、

  z_zoom ≈ α · z_direct + β

の `α` と `β` を推定してください。

  - `α` が窓幅と相関するか。**これが本測定の主結論**
  - `β` が 0 とみなせるか。§8.1.1 は「`z` は平行移動項を持たない」と書いており、
    その主張の検証になる
  - 残差の大きさ。α と β では説明できない部分がどれだけあるか

`z` の原点は頭部中心付近の相対量なので、**生の `z` を 1 点ずつ比べても意味が
ありません。** 全 478 点をまとめて 1 つの (α, β) に当てる形にしてください。

### 実写での追認

take01（姿勢がドリフト）・take02（静止）・take03 を zoom 経路で通し、

  - 窓幅の実際の変動範囲（そもそも窓が変わらないなら、この経路の risk は低い）
  - 窓幅と `d_3d` の相関
  - 窓幅と α の相関
  - **zoom 経路での take01 / take02 の表示値中央値の差**（§12.2 の 0.031pt が
    この経路でも保たれるか）

最後の 1 行が、E1 の中心的な発見が実経路で生き残るかの答えです。
