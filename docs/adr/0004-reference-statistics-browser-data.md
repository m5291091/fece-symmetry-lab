# ADR-0004: 参照統計ブラウザの同梱データ形式と配置

- Status: Accepted
- Date: 2026-08-15
- Related requirements: FR-037, §9.5, §10.7, §10.9, §16, AC-REFERENCE-01〜04

## Context

UTKFace（18〜75 歳、姿勢ゲート通過 14,754 件）を `symmetry-3d/1.0.0` で測定した探索的記述統計を、アプリ内で人種・性別・年齢で絞り込んで閲覧できるようにしたい（FR-037）。絞り込みは各軸で複数選択でき、未選択の軸は絞り込まない。

材料は notebook（`research/utkface-symmetry/`）が出力した 4 ファイルで、リポジトリ直下に散らばっていたものを `data/` へ集約した。

| ファイル | 内容 |
|---|---|
| `utkface_symmetry3d_records.csv` | 個票 14,754 行。1 枚ごとのスコアと**ファイル名**を含む。8.4MB |
| `utkface_symmetry3d_group_means.csv` | 1 軸ごとの集計（age 58 / age_band 6 / race 5 / gender 2 の 71 行） |
| `utkface_symmetry3d_measurement_stats.csv` | 全件の統計 |
| `utkface_symmetry3d_summary.json` | 実行条件・件数・警告文 |

3 つの判断が要る。**(a)** 何をアプリへ同梱するか。**(b)** どの統計量を出すか。**(c)** 同梱物をどこへ置くか。

## Decision

### (a) 個票を同梱せず、事前集計セルテーブルを新たに生成して同梱する

`(race, gender, age)`（`age` は 1 歳刻み、18〜75）を最小粒度とするセルテーブルを `scripts/build_reference_dataset.py` で生成し、それだけを同梱する（§9.5）。各セルは `count` と、7 指標それぞれの `mean` と `m2`（二乗偏差和 Σ(x − mean)²）を持つ。

既存の 2 案はいずれも要件を満たさない。**個票 8.4MB の同梱**は、1 枚ごとのスコアとファイル名を配布物へ入れることになり §10.9-1 に反する。**既存 `group_means.csv` の流用**は、1 軸ごとの平均しか持たないため人種 × 性別 × 年齢の組み合わせ絞り込みに使えない。

`sum` と `sum_of_squares` ではなく `mean` と `m2` を持たせる。任意のセル集合の和集合について平均と標本標準偏差を厳密に再構成でき、`Σx²/n − mean²` 型の実装が持つ桁落ち（平均に対し分散が小さいとき負の分散を返しうる）を避けられるためである。合併は Chan らの並列アルゴリズムに従う（式は §9.5）。

セル粒度を年齢帯へ丸めない。丸めると 1 歳刻みの範囲指定を後から作れなくなる。理論最大 580 行と小さく、丸めて節約する動機がない。

### (b) 中央値と 95% 信頼区間を v1 では出さない

中央値は個票の順序統計量を、95% CI は bootstrap 再標本化を要する。どちらもセルの `(count, mean, m2)` からは**原理的に**復元できない。個票を同梱しない (a) の帰結として、v1 が出せるのは平均と標本標準偏差だけである。UI にもその制約を明記する。

出すために個票を同梱するのは (a) の判断を覆すことであり、採らない。将来これらが要るなら、中央値・分位点は分位スケッチ（t-digest 等）を、CI は正規近似を、それぞれ別の凍結アセットとして版を分けて追加する。

### (c) 配布アセットを `configs/reference/` へ置き、`data/` を丸ごと非追跡にする

`data/` は `.gitignore` の `data/*` で丸ごと除外し、`!data/README.md` だけを例外とする。`models/*` + `!models/.gitkeep` と同じ作法である。**顔由来データがリポジトリへ入らないこと（不変条件 1）を、人の注意力ではなく機構で保証する**ためであり、置き場さえ守れば名前の付け方で漏れることがない。

配布アセットを `data/` の中へ置くと、この「100% 除外」を `!` の例外で崩すことになる。代わりに `configs/reference/` へ置く。`configs/` は既に「版管理され hash 検証される凍結バンドル」の置き場（`configs/metrics/symmetry-3d-v1.json`、`configs/model-manifest.json`）であり、参照セルテーブルはまさにそれである。

生成元 notebook は `research/utkface-symmetry/` へ出して追跡する。配布アセットの生成元であり再現性の正本なので、非追跡の `data/` に置けない。`src/` からは参照しない。

## Consequences

- 参照ページは平均と標本標準偏差だけを扱う。中央値・CI・分布形状を求める要望は v1 では応えられず、アセットの版を分けた追加でしか応えられない。
- `scripts/build_reference_dataset.py` は人間が 1 回実行し、成果物をコミットする。アプリの実行経路からは呼ばない（§10.9-3）。決定論的に出力し（行順は race → gender → age 昇順、浮動小数は固定桁）、同じ入力から常に同じ sha256 を出す。
- 生成スクリプトは自己検証を持つ。生成したセルから 1 軸集計と全件集計を再構成し、`group_means.csv` と `measurement_stats.csv` の該当値と一致しなければ非ゼロ終了する。一致しない生成物がリポジトリへ入る経路を塞ぐ。
- `data/` を丸ごと除外したことで、`docs/capture-protocol.md` の「リポジトリ直下に置いてよい」という保管規則は失効し、`data/takes/` を正とする形へ改めた。`*.mov` と `take*.json` の従来 pattern は `data/` の外へ取りこぼした場合の受け皿として残す。
- notebook を追跡対象にしたことで ruff の既定探索（v0.6 以降は `*.ipynb` を含む）へ入り、`ruff check` 15 件・`ruff format --check` 1 件で `scripts/verify.py` が落ちた。`pyproject.toml` の `[tool.ruff]` へ `extend-exclude = ["*.ipynb"]` を追加した。notebook を本体と同じ規約へ合わせると、Colab で実行した記録そのものが書き換わって再現性が崩れるためである。
- **件数 1 のセルでは、集計が個票の匿名化にならない。** 実データでは 536 セル中 36 件が該当し、そこでは `mean` が 1 枚の測定値そのもの、`m2` は 0 になる。UTKFace が公開データセットである以上、同じ選別条件を再現できる者は該当画像を特定できる。セル粒度を `(race, gender, age)` の 1 歳刻みに保つ以上これは避けられず、粒度を粗くする（年齢帯へ丸める）と本 ADR (a) の目的である組み合わせ絞り込みが成立しなくなる。**「集計済みだから安全」という説明は採らず、§10.9-2 に実態を書く。** 表示側は §9.5 のしきい値 8 でこの経路を塞ぐが、それは UI の話であって CSV 自体の性質は変わらない。件数の少ないセルを落とす k-匿名化は、1 軸集計・全件集計が `group_means.csv` と合わなくなり自己検証を壊すため、採らなかった。
- 参照統計は利用者自身の測定結果と結び付けない（§10.7）。偏差値・順位・パーセンタイル・「平均より上／下」を作らず、両者を同じ画面へ並べない。この制約は本 ADR の (a)〜(c) とは独立で、データ形式を変えても緩まない。
- UTKFace は非商用研究限定である。同梱物が集計値だけであっても出典・ライセンス条件は残るため、画面と `.meta.json` の双方へ記録する。
