# ADR-0006: 利用者の測定値へ同年齢・同性別の参照平均を併記する（FR-039）

- Status: Accepted
- Date: 2026-08-16
- Related requirements: FR-039, FR-037, FR-038, §1.3.1 不変条件 5, §5.1, §5.2, §5.3, §9.5, §10.7, §10.9, §10.12, AC-BASELINE-01〜04

## Context

FR-037 で同梱した参照統計セルテーブル（`utkface-symmetry-3d-cells/1.0.0`、§9.5）は、
`(race, gender, age)` ごとに 7 指標の `count` / `mean` / `m2` を持つ。この 7 指標は、
Camera の HUD と Image の吹き出しが表示している 6 つの数値——全体の対称度・全体のスコア・
部位別 4 つ——と 1 対 1 で対応している。

一方 §10.7 は「**利用者自身の測定結果と参照統計を結び付けず、偏差値・順位・パーセンタイル・
「平均より上／下」を算出も表示もせず、両者を同じ画面へ並べない**」と定めていた。FR-037 の
参照ページはこの禁止に従い、絞り込みと記述統計だけを表示する独立したページとして作られている。

利用者（プロダクトオーナー）は 2026-08-16 に、**吹き出しの各スコアへ同年齢・同性別の平均と
差を併記する**ことを指示した。これは上の禁止に正面から当たる。`CLAUDE.md` §3 の優先順位では
ユーザー指示が `requirement.md` より上位であり、変更は可能である。判断すべきは
「解除するかどうか」ではなく、**どこまで解除し、何を解除しないか**である。

4 つの判断が要る。**(a)** 不変条件 5 と §10.7 をどこまで解除するか。**(b)** 母集団を
どう選ぶか。**(c)** 年齢ゲート（FR-038）との関係をどうするか。**(d)** 表示の形をどうするか。

## Decision

### (a) 解除するのは「同じ場所へ並べること」だけで、順位化は解除しない

**解除する。** ただし範囲は、対応する測定値の隣へ「母集団の平均」と「表示値との差」を
置くことに限る。**偏差値・順位・パーセンタイル・分位・合否・「平均より上／下」という語と、
分布上の現在位置を示す図（ゲージ・順位バー・ヒストグラム上のマーカー）は引き続き作らない**
（§10.12-1）。

この線引きの根拠は、両者の性質の違いである。平均と差は**可逆な引き算**であり、測定値と
参照値という 2 つの独立した数を並べているだけで、新しい主張を含まない。対して偏差値・
順位・パーセンタイルは、母集団の分布の形を使って個人を**一次元の順序へ写す**変換であり、
その順序はデータセットの撮影条件・注釈・構成比をそのまま個人の評価として引き受けてしまう。
§10.7 が守ろうとしていたのは後者であって、前者ではない。

**参照ページ（FR-037）側の禁止は解除しない。** 参照ページは従来どおり利用者の測定値を
持ち込まない。解除は Camera の HUD と Image の吹き出しに閉じる。理由は 2 つある。参照
ページの目的が「群ごとの記述統計を読む」ことであって個人の位置づけではないこと、そして
禁止の解除範囲は小さいほど後から戻しやすいことである。

### (b) 母集団は「参考年齢（1 歳）× 参考性別」とし、人種では絞らない

**人種で絞らない。** アプリは人種を推定せず（不変条件 7）、推定した人種で母集団を選ぶ経路を
作らない。UTKFace の人種注釈は配布時の注釈であり、アプリ側にそれを解決する手段が無い。
「絞れないから全件」ではなく、**絞る手段を持たないことが正しい状態**である。

**年齢は 1 歳刻みのセルをそのまま使う。** 実データでは `(gender, age)` を全人種で合算した
件数が最小 11 件（female・74 歳）・最大 787 件（female・26 歳）で、**116 通りすべてが §9.5 の
しきい値 8 件を満たす**。年齢帯（18-24 等）へ丸める必要が無く、丸めれば「20 歳の平均」が
「18〜24 歳の平均」にすり替わる。しきい値の判定は実装側に残す——将来データを差し替えたとき
に静かに条件が崩れないようにするためであり、現時点で発火しないことを理由に省かない。

年齢の丸めは**表示している参考年齢と同じ丸め**（`round`、偶数丸め）を使う。ここがずれると、
吹き出しが「参考年齢 27 歳」と言いながら「28 歳の平均」を出すことになる。

### (c) 参考年齢を表示していないときは併記しない

**FR-038 のゲートが参考年齢を隠しているときは、母集団も出さない。** これは安全側の既定と
いうより、ゲートの設計そのものを守るための条件である。§10.11-2 は「ゲートの内部判断を
利用者へ属性として提示しない」と定めているが、参考年齢を隠したまま「20 歳・男性の平均」と
書けば、隠したはずの判断が母集団の年齢から復元できてしまう。**併記は、参考年齢・参考性別を
実際に表示しているときの上乗せとしてのみ存在する。**

同じ理由で、推定が無いとき・利用者が年齢性別表示を切ったときも併記しない。

### (d) 表示は「平均」と「符号付きの差」の 2 つだけ、単位は表示値と同じにする

対応する測定値のすぐ下へ 1 行ずつ置く（§5.1）。差は表示値と同じ単位で示し、色・矢印・
大小の演出を伴わせない（§5.2）。**参照統計は表示だけに使い**、指標・`metric_version`・
`config_fingerprint`・エクスポート列・EMA・品質ゲート・年齢ゲートのいずれも変えない。
表示値が欠測（`—`）の項目には差を出さず、0 で埋めない（不変条件 11）。

## Consequences

- **§10.7 の禁止文が 2 つに分かれる。** 「参照ページへ測定値を持ち込まない」は残り、
  「両者を同じ画面へ並べない」は FR-039 の範囲で解除される。以後この節を読むときは、
  どちらの話をしているのかを §10.12 で確かめること。
- **不変条件 5 に初めて例外ができる。** 参考年齢・参考性別は「別の結果」であり続けるが、
  「どのセルを読むか」の選択にだけ使われるようになる。**両者の間に相関・因果・優劣がある
  という主張は、文言・図・配置のいずれでも行わない。** この ADR は前例にならない——
  参考年齢・参考性別を他の用途へ使うときは、改めて §1.3.1 の判断からやり直すこと。
- **利用者は自分の値が平均より小さいことを知りうる。** 差を出す以上これは避けられず、
  「平均より下」という語を使わないことで防げるものでもない。受け入れたうえで、その差が
  何に由来するのか（UTKFace と固定した選別条件、撮影条件・注釈・構成比・ランドマーク
  検出の群ごとの挙動差）を併記と同じ場所へ置く。§5.3 の禁止語と、基準値・判定線を
  提示しない規律はそのまま適用される。
- **「全体のスコア」の差は見かけが大きくなる。** §8.6.7 の表示スケールは実測が集まる
  範囲（ずれ 1.0〜5.0%）へ引き伸ばしてあるため、対称度で 2 ポイントの差が点では 50 点
  動く。目盛りを引き伸ばした分だけばらつきも拡大するという既存の開示（`SCORE_SCALE_CAPTION`）
  が、併記の場面でいっそう重要になる。
- **参照データが読めなくても何も止まらない。** 併記だけが消え、左右差・参考年齢・参考性別・
  詳細結果・エクスポートは従来どおり動く（不変条件 12）。`ReferenceBrowser` が既に持つ
  失敗分離をそのまま使い、読み込みは再試行しない。
- **将来データを差し替えるときの条件が 1 つ増える。** `(gender, age)` の全 116 通りが
  8 件以上であることは現行データの性質であって、スキーマの保証ではない。差し替え時は
  この分布を確かめること。満たさないセルでは併記が静かに消える（誤った平均は出ない）。
